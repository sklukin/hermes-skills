# hermes-skills

Навыки для агентов [@agentmakerrbot](https://t.me/agentmakerrbot).

## Структура

```
skills/
  <имя-навыка>/
    SKILL.md          — обязателен: инструкция агенту плюс фронтматтер
    references/       — необязательно: справочные материалы, которые агент читает по нужде
    scripts/          — необязательно: скрипты, которые агент запускает
```

Путь именно такой: `hermes skills tap` ищет навыки в каталоге `skills/` и нигде больше, а
идентификатор для установки складывается как `sklukin/hermes-skills/<имя-навыка>`.

## SKILL.md

```markdown
---
name: имя-навыка
description: "Одна строка: что навык делает. Её читает модель, решая, брать ли навык."
version: 1.0.0
license: MIT
platforms: [linux]
metadata:
  hermes:
    tags: [коротко, о чём, навык]
---

# Имя навыка

Что это и когда применять — одним абзацем.

## Как действовать

1. Шаги, которые агент выполняет.
2. Пиши инструкции агенту, а не описание для человека: он читает этот файл как руководство.

## Чего не делать

- Границы: чего навык не должен делать даже по прямой просьбе.
```

`description` — единственное, что видит модель до того, как откроет навык. Пишите её так, чтобы по
ней было понятно, когда навык нужен.

## Правила

- **Никаких секретов.** Репозиторий публичный: ключи, токены и адреса внутренних систем сюда не
  попадают ни в каком виде.
- **`scripts/` исполняется на машине агента.** Всё, что там лежит, должно быть безопасным при
  запуске без присмотра: никаких удалений вне своего каталога, никакой отправки данных наружу.
- **Имена не должны совпадать со встроенными навыками Hermes** (их больше пятидесяти:
  `hermes skills list --source builtin`). Совпадение имени ломает учёт обновлений.
- **Версия растёт при каждом изменении** — по ней Hermes понимает, что навык пора обновить.

## Установка

```sh
hermes skills tap add sklukin/hermes-skills
hermes skills install sklukin/hermes-skills/<имя-навыка> --yes
hermes skills list --source hub
```

Установленный навык виден агенту сразу, перезапускать его не нужно.
