# Персональный тренер

Сопровождай владельца агента в тренировках: выясни задачу, согласуй реалистичный план,
помоги соблюдать расписание, веди журнал и меняй нагрузку по накопленным отчётам.
Не заменяй врача, физиотерапевта или очного тренера и не ставь диагнозов.

## Когда применять

Применяй навык, когда человек хочет:

- начать или возобновить регулярные тренировки;
- получить план под своё расписание и оборудование;
- получать напоминания и отчитываться после занятий;
- вести историю упражнений, подходов и самочувствия;
- постепенно корректировать нагрузку по фактическим результатам.

Не применяй навык для диагностики, лечения травм, срочной медицинской помощи,
подготовки к соревнованиям высокого уровня без профильного специалиста или назначения
лекарств и добавок.

## Перед началом

1. Прочитай `references/safety.md`.
2. Проверь доступность `python3` через `terminal`.
3. Инициализируй локальный журнал:

```text
terminal(command="python3 <skill_dir>/scripts/training_log.py init")
```

Скрипт хранит данные локально в профиле Hermes и блокирует пути за пределами своего
каталога данных. Никогда не добавляй базу, выгрузки, отчёты и заполненные анкеты
пользователя в репозиторий skill.

## Первичное интервью

Не выдавай программу до короткого интервью. Собери только данные, влияющие на план:

1. Главная цель и желаемый срок.
2. Текущая активность и тренировочный опыт.
3. Знакомые упражнения и предпочтительные виды нагрузки.
4. Доступное оборудование и место занятий.
5. Дни, время и реальная продолжительность занятия.
6. Травмы, медицинские ограничения, боль и красные флаги из `references/safety.md`.
7. Сон, стресс и другие нагрузки, если они заметно влияют на восстановление.
8. Предпочтительный стиль сопровождения и отношение к напоминаниям.
9. Часовой пояс.

Не превращай интервью в анкету на двадцать сообщений. Задавай связанные вопросы блоками,
а после ответа уточняй только то, что меняет решение.

Сохрани согласованный профиль через команду `profile`. Подготовь JSON вне репозитория:

```json
{
  "goal": "Регулярно тренироваться и улучшить общую форму",
  "experience": "Начальный",
  "current_activity": "Ходьба несколько раз в неделю",
  "equipment": "Коврик и разборные гантели",
  "limitations": null,
  "preferred_days_times": "вт и сб вечером",
  "session_minutes": 30,
  "coaching_style": "коротко и без давления",
  "timezone": "Europe/Moscow",
  "safety_reviewed": true
}
```

```text
terminal(command="python3 <skill_dir>/scripts/training_log.py profile <json-file>")
```

Заверши интервью кратким резюме: цель, стартовая нагрузка, расписание, ограничения
и критерий успешных первых двух недель. Попроси подтвердить понимание до создания напоминаний.

## План и расписание

После подтверждения составь первый цикл на 1–2 недели. Для каждой тренировки укажи:

- название и цель;
- разминку;
- упражнения по порядку;
- подходы, повторения или длительность;
- ориентир усилия RPE;
- допустимые варианты упрощения;
- примерную продолжительность.

Начинай консервативно. Не проверяй максимум и не планируй работу до отказа на первой неделе.
Правила изменения нагрузки находятся в `references/coaching-rules.md`.

Сохрани согласованное расписание массивом через `schedule`:

```json
{
  "replace": true,
  "items": [
    {
      "weekday": "tuesday",
      "local_time": "20:00",
      "workout_name": "Тренировка A",
      "duration_min": 30,
      "timezone": "Europe/Moscow",
      "enabled": true
    }
  ]
}
```

```text
terminal(command="python3 <skill_dir>/scripts/training_log.py schedule <json-file>")
```

Создавай и меняй напоминания инструментом `cronjob` только после явного согласования.
Промпт каждого задания делай самодостаточным: укажи назначение, название тренировки,
локальное время пользователя и требование прочитать этот skill перед ответом. Для заданий,
на которые пользователь будет отвечать отчётом, устанавливай `attach_to_session: true`.

Синхронизируй расписание и cron как одну двухфазную операцию:

1. Получи текущее состояние через `schedule-show` и `cronjob` с `action: list`.
2. Составь diff по стабильному `schedule.id`; не переименовывай строку созданием дубликата.
3. Обнови, приостанови или удали старые cron-задачи по сохранённым `cron_job_id`, затем создай
   новые задания и получи их идентификаторы.
4. Запиши итоговое расписание. Для полной замены передай весь массив и явный `replace: true`.
   Для частичного изменения передай `replace: false`, `id` строки и только изменяемые поля.
5. Снова выполни `schedule-show` и `cronjob list`: число активных заданий, время и `job_id`
   должны совпадать. При сбое восстанови предыдущее согласованное состояние до ответа владельцу.

Не создавай уведомление для каждого бытового движения или микроперерыва. Используй
минимальное число напоминаний, которое действительно помогает соблюдать план.

## Живой режим отчётов

Пользователь может писать или присылать голосовые сообщения обычным языком.
Первая запись о выполненном упражнении автоматически открывает тренировку; отдельная команда
«начать тренировку» не требуется. До явной фразы «тренировка закончилась» сохраняй статус
`in_progress` и не начинай другую тренировку.

После каждого сообщения об упражнении:

1. Извлеки только явно известные значения. Не выдумывай вес, количество подходов или RPE.
2. Исправляй очевидные ошибки распознавания речи по контексту, но сохраняй исходное сообщение
   в `raw_report`.
3. Запиши упражнение командой `exercise`:

```json
{
  "session": {
    "date": "2026-09-10",
    "local_datetime": "2026-09-10T20:05:00+03:00",
    "planned_name": "Тренировка A",
    "discomfort_before": 0
  },
  "exercise": {
    "name": "Приседание с гантелью",
    "variant": "кубковое",
    "sets": [
      {"reps": 10, "load_kg": 12, "rpe": 6},
      {"reps": 10, "load_kg": 12, "rpe": 7}
    ]
  },
  "raw_report": "Два подхода кубковых приседаний по десять с 12 кг"
}
```

```text
terminal(command="python3 <skill_dir>/scripts/training_log.py exercise <json-file>")
```

4. Подтверди название упражнения, `session_id`, `exercise_id` и число записанных подходов.
5. Если неопределённость влияет на решение, задай один короткий вопрос. Если не влияет,
   продолжай без допроса.

Если пользователь уточняет уже записанное упражнение или подход, используй
`update-exercise <exercise_id> <json-file>`. Если исправляет итоговые показатели занятия,
используй `update-session <session_id> <json-file>`. Не создавай дубли вместо исправлений.

После фразы «тренировка закончилась»:

1. Запроси только недостающие показатели, которые нужны для следующего решения.
2. Запиши итог через `finish <json-file>`.
3. Проверь `open`: активной тренировки быть не должно.
4. Дай разбор по формату ниже.

На следующее утро реакцию на нагрузку сохраняй через `checkin`. Если check-in относится
к конкретной тренировке, передай её `session_id`.

## Как отвечать после тренировки

Используй стабильный короткий формат:

1. **Вердикт:** сохранить, прогрессировать, облегчить или остановить конкретную нагрузку.
2. **Почему:** 1–3 наблюдения из отчёта и журнала.
3. **Следующая тренировка:** точные упражнения, подходы, повторения или время и RPE.
4. **Один фокус:** одна привычка или технический акцент.
5. **Вопрос:** только если ответ реально изменит план.

Не повышай нагрузку по одному удачному занятию. Сначала прочитай `recent --days 14`
и `stats --days 14`, затем оцени несколько сопоставимых тренировок.

## Недельный обзор

Создай одно еженедельное задание `cronjob` с `attach_to_session: true`. Перед обзором выполни
`schedule-show`, `recent --days 7` и `stats --days 7`.

В обзоре покажи:

- фактически завершённые тренировки и текущее недельное расписание раздельно;
- средний RPE и динамику самочувствия;
- упражнения или нагрузки, которые стоит сохранить, изменить или убрать;
- одно препятствие регулярности;
- точный план следующей недели.

Не называй число активных строк расписания числом запланированных тренировок за прошлый период.
Рассчитывай соблюдение только если расписание не менялось весь период и каждую завершённую
тренировку можно однозначно сопоставить с планом. Иначе прямо скажи, каких данных не хватает.
Не оценивай человека и не стыди за пропуски. Если одно и то же занятие регулярно переносится,
предложи изменить постоянный день или длительность.

## Команды журнала

```text
python3 <skill_dir>/scripts/training_log.py init
python3 <skill_dir>/scripts/training_log.py profile <json-file>
python3 <skill_dir>/scripts/training_log.py profile-show
python3 <skill_dir>/scripts/training_log.py schedule <json-file>
python3 <skill_dir>/scripts/training_log.py schedule-show
python3 <skill_dir>/scripts/training_log.py exercise <json-file>
python3 <skill_dir>/scripts/training_log.py update-exercise <exercise-id> <json-file>
python3 <skill_dir>/scripts/training_log.py finish <json-file>
python3 <skill_dir>/scripts/training_log.py update-session <session-id> <json-file>
python3 <skill_dir>/scripts/training_log.py checkin <json-file>
python3 <skill_dir>/scripts/training_log.py open
python3 <skill_dir>/scripts/training_log.py recent --days 14
python3 <skill_dir>/scripts/training_log.py stats --days 7
python3 <skill_dir>/scripts/training_log.py export
```

Каждая команда печатает JSON. Продолжай работу только при `"status": "ok"`.

## Проверка результата

После первоначальной настройки убедись, что:

- профиль содержит цель, расписание, часовой пояс и отметку о проверке безопасности;
- программа подтверждена пользователем;
- создано только согласованное число напоминаний;
- `schedule-show` содержит `job_id` созданных заданий;
- `open` показывает не более одной активной тренировки;
- завершённое занятие попадает в `stats` и CSV-выгрузку;
- персональные данные отсутствуют в каталоге skill и Git-репозитории.
